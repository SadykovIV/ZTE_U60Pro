# Таймер гостевой VPN-сети на B31

При первой настройке (`configure.lua apply`) и каждом явном включении (`enable`)
для двух принадлежащих VPN секций `wireless.guest_2g` и `wireless.guest_5g`
устанавливается `guest_active_time='0'`. Это штатное значение «без ограничения».
Перед включением проверяются обе секции: тип `wifi-iface`, сеть `vpn` и мост
`br-vpn`. Несовпадение останавливает операцию до первой записи UCI. Маркер
незавершённой настройки Wi-Fi также продолжает блокировать включение.

## Основание

В штатных исходниках B31 обнаружена следующая цепочка:

- `config.js`: `ACTIVE_TIME_MODES` сопоставляет `Free` со строкой `0`.
- `wifi_guest.js`: выбранное значение передаётся в `GuestSSIDActiveTime`.
- `service_rpc.js`: `setWifiMeshGuestSwitch` записывает
  `guest_active_time = 60 * GuestSSIDActiveTime` сразу для обоих гостевых AP.
  Таким образом, часы из UI становятся минутами в конфигурации; ноль сохраняется.

SHA-256 исследованных файлов:

| Файл | SHA-256 |
| --- | --- |
| `config.js` | `519ce0d12a6da646ff1b402002a6747c8310985ef5da0b84dae30697348dc2ce` |
| `wifi_guest.js` | `ac1bf2343c29e370bbde55e50b467fe5361a79b3bdfc4812483c4fc0718aefb4` |
| `service_rpc.js` | `5c487cf7c39d15eda480dbb739db027bd36aaa880eaf3d7c98437ad320c2c0d5` |

`guest_remaining` — отдельный счётчик. Штатный setter выше его не записывает,
поэтому включение VPN также не меняет это поле. Полная исходная конфигурация
`wireless` уже сохраняется менеджером перед первым применением. Режим `restore`
теперь возвращает из неё оба поля `guest_active_time` и `guest_remaining`, включая
исходное отсутствие каждого поля. Обычное выключение и изменение имени/пароля
не меняют эти таймеры.

## Границы

Правка не меняет сон всего устройства или основного Wi-Fi. Отдельный штатный
`getSleepMode` читает `zwrt_sleep.ztmp_time.SysIdTime`, а `setSleepMode` передаёт
`ufiSleepTime` в `zwrt_zte_sleep_faw.wakelock.set_ufi_sleep`. Смысл `-1` и единицы
этого отдельного параметра не установлены по исследованным трём файлам.

Это устранение известного ограничения гостевой сети, а не доказательство причины
каждого самопроизвольного отключения. Защита VPN по-прежнему может выключить AP
при ошибке firewall или несовпадении моста. После изменения встроенного скрипта
нужны пересборка контроллера и обновление соответствующих хэшей; сам этот этап
не устанавливает ничего на модем и не подтверждает аппаратный результат.

## Проверка

`python3 MacIMEI/Tests/test_vpn_wifi_settings.py` выполняет настоящий Lua-скрипт
с UCI в памяти. 21 группа проверок включает исходные настройки, переход
`apply → enable → restore`, отсутствие исходных полей, сохранение счётчика,
повторное включение, отказ при чужой/отсутствующей секции и незавершённых
настройках, неизменность основных AP и глобальных параметров.
