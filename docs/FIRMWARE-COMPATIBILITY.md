# Совместимость прошивок MU5250 / U60 Pro

Доступность определяется отдельно для каждой операции по текущему устройству,
файлам, ABI и ответам штатных интерфейсов. Общего флажка отключения проверки
прошивки нет. Название B31/B28/B04/B02 само по себе не разрешает запись.
Проверка предпосылок и успешный локальный тест не заменяют проверку на модеме.

## Матрица операций

«Проверки» означает, что код выполняет собственные измеряемые проверки операции;
это не отметка об аппаратной проверке. «Профиль» означает точный адаптер по
проверенным файлам. «Нужны данные» — отсутствуют необходимые доказательства для
этого адаптера, а не запрет по одному названию версии.

Условие `absent` означает доказанное отсутствие обычного файла, а не ошибку
чтения, симлинк или неизвестный хэш. При IMEI-транзакции это значение сохраняется
в backup/journal: появление образа после копии меняет привязку и блокирует
восстановление. Проверка реальных NV/EFS-данных обязательна независимо от версии.

## Что собирать для другой прошивки

Новый раздел меню не нужен. В существующей **Диагностике** есть **Собрать данные
для адаптации прошивки**; подсказка доступна также в настройке подключения и
ошибках неподдерживаемых компонентов. Открытие раздела не запускает сбор.
Действие сохраняет один ZIP по выбранному SSH-подключению, без автоматической
отправки. Если SSH ещё недоступен, **Сохранить логи и журналы** сохраняет локальную
причину остановки подготовки; такой архив не доказывает версию удалённого модема.

Минимальная исходная информация: реальные integrate/inner/kernel, архитектура,
root/канал, привязка CID/boot в редактированном отчёте, наличие и хэши компонентов,
штатные методы RPC, зависимости/ABI, metadata startup и точная причина отказа.
Для экрана/нового IPA нужны также оригинальные системные файлы, поэтому уже
существующий объединённый сбор включает ограниченный фиксированный набор
бинарников/шрифтов и новый пассивный отчёт. Правила состава и ограничений описаны
в [FIRMWARE-ADAPTATION-DATA](FIRMWARE-ADAPTATION-DATA.md).

Пароли, SSH-ключи, пользовательские VPN/APN/SIM-профили и сырые NV/EFS-значения
не экспортируются. Native DIAG/QMI-пробы сохраняют только статус/структуру,
не выполняют NV write, APDU, переключение SIM или radio reset. Архив с vendor
бинарниками передают лично для анализа; его нельзя включать в публичный релиз.

Основные источники реализации: `FirmwareResearch/probes.json`,
`Onboarding/setup-agent.sh`, `TTL/manager.sh`, `VPN/install.sh`,
`launcher/abi-profiles.json`, `ScreenLocalization/font.patch*.json`,
`Core/ImeiEngine.Transaction.cs`, `Engine.swift` и `esim/resources.rs`.
