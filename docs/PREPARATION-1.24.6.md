# 1.24.6 build 47: исправление подготовки модема

macOS **build 47**, Windows **1.24.6.0**, агент **2.9.0-esim.4**.

## Что показали настоящие журналы

На подключённом B31 восстановление включило USB ADB. Программа получила root и подтвердила устройство, но остановилась с `DIRECTORY_MODE`: штатные `/data/bin`, `/data/local` и `/data/local/tmp` имеют права 777. До запуска SSH дело не дошло; порты 22 и 2222 были закрыты.

У SashaRIP проверка ключа успешно расшифровала свежий бэкап для `FLY_CN_MU5250V1.0.0B13 / BD_FLYMODEMMU5250V1.0.0B28`, подтвердив 173 записи. Подготовка подтвердила root ADB и завершилась с `DROPBEAR_ABI`. Установщик проверял запуск переданных файлов без подготовки права исполнения. Точное право файла в архиве SashaRIP отсутствует; отдельная несовместимость библиотек на B28 этим отчётом не исключена.

## Как исправлена установка

Приватный каталог `/data/zte-imei-studio` создаётся с правами 700 под проверенным `/data`. В нём находятся временные файлы, приватные журналы установки, Dropbear и файлы запуска. Штатные общие каталоги не меняются. После проверки хэша и ARM64-формата бинарники получают право исполнения перед проверкой запуска.

Dropbear запускается на **2222**. Проверяется реальный слушатель этого порта и его процесс. Один успешный запуск процесса не считается готовым SSH. Доверие к ключу сервера закрепляется через проверенный USB ADB, последующие команды используют строгую проверку ключа.

После сброса может остаться старый агент. При обычной подготовке, если он не работает, исходный бинарник сохраняется с контрольной суммой перед заменой текущей сборкой. Корректный старый файл запуска переносится как проверенные данные в приватный каталог с сохранением пароля; для входа нужен прежний пароль. При отсутствии файла запуска применяется пароль, введённый при подготовке. Работающий агент можно обновить через установку агента по SSH либо выбрать описанный ниже принудительный режим.

Журналы уже отправленного restore/install не удаляются для повторной попытки. Готовый root ADB позволяет продолжить restore без нового восстановления и без Web-пароля. Ранее отправленная установка использует свой сохранённый путь и исходный удалённый сценарий.

## Пароли и повторные операции

Пароли Web и агента и ручной ключ бэкапа удерживаются в памяти окна для выбранного устройства. Проверка ключа, ошибка подготовки, смена страницы и обновление не очищают их. Смена адреса, порта или контекста ключей и закрытие приложения очищают значения. Сохранения этих полей в настройки и журналы нет.

«Обновить» повторно проверяет выбранный SSH. После ошибки состояние подключения очищается, а подготовка и повтор подключения остаются доступны. После перезагрузки модема создаётся новый проверенный SSH-сеанс с сохранением идентичности устройства и доверия к ключу.

## Повторная проверка SashaRIP

1. Распаковать **весь** Windows portable ZIP версии 1.24.6.0.
2. Указать адрес модема, пароль штатного Web и пароль агента. Ключ бэкапа можно оставить пустым: в присланном журнале он уже успешно проверен.
3. Выполнить первоначальную подготовку. При существующем root USB ADB восстановление бэкапа не требуется.
4. После успеха проверить SSH 2222, обновление сведений и повторную операцию без перезапуска программы.
5. При ошибке выгрузить общий диагностический архив. Сохранить незавершённый журнал: он предотвращает повторную отправку изменений.

Проверка B31 выполняется на подключённом устройстве. Windows UI и сервисы проверяются на macOS; новая установка на B28 и нативный Windows требуют повторной проверки у SashaRIP. Каталог поставки — `dist/1.24.6`; результаты и контрольные суммы сохраняются рядом с ZIP.

## Проверка подключённого B31

После первой проверки был сохранён готовый журнал SSH, но установщик оставил прежний агент. Для этого уже отправленного журнала выполнено отдельное восстановление: подтверждены исходные контрольные суммы и процесс, сохранены агент и файл запуска, заменены только эти два файла. Исходный бэкап и ранее отправленное восстановление не повторялись. Это отдельная исследовательская операция, а не обещание автоматического восстановления любого прерванного состояния.

Текущий код подготовки продолжил тот же журнал, подтвердил агент `2.9.0-esim.4`, вход с новым паролем, строгий SSH на 2222 и завершил исходный commit. Исправленный сценарий первоначальной замены неактивного старого агента проверен отдельно файловыми тестами; новый сброс модема ради его повторной проверки не выполнялся.

Затем на том же B31 выполнена отдельная принудительная подготовка текущим установщиком. Вход с новым паролем агента и commit прошли; незавершённое локальное намерение закрыто. Две свежие проверки подтвердили совпадение USB/SSH и доступ на 2222 со строгой проверкой ключа. Ключи сервера и inode работающего Dropbear сохранились. Исходный бэкап и новый снимок перед принудительной заменой прошли проверку контрольных сумм; в новом снимке сохранён предыдущий файл запуска. Специально подготовленный временный каталог завершённой установки, включая допустимый `incoming-UUID`, удалён; журнал сохранён.

После этого производственный AppModel в одном процессе выполнил подключение за 47,666 с и два обновления за 7,197 и 7,085 с. Во всех трёх случаях подтверждены новый SSH-сеанс, то же устройство и та же загрузка модема; ошибки разделов отсутствовали, каждое действие завершилось без оставшегося состояния занятости. Это отдельный прогон после принудительной подготовки, без перезапуска приложения и без запроса чтения eSIM.

Эти проверки не включали заводской сброс, повтор restore, запись IMEI или запись eSIM.

## Принудительная подготовка и временные файлы

В параметрах первоначальной подготовки включите «Принудительная подготовка: переустановить агент и SSH» и задайте пароль агента. Этот режим предназначен в том числе для повторной подготовки после заводского сброса, когда в памяти модема остались старые файлы программы.

Сначала установщик подтверждает устройство и сохраняет текущие компоненты с контрольными суммами. Это происходит до остановки принадлежащего программе агента и до замены файлов. Агент заменяется текущей сборкой и получает введённый пароль. SSH работает на **2222**; существующие проверенные ключи и работающий проверенный слушатель сохраняются. Чужой процесс или непроверенный слушатель не останавливается.

Файлы расположены под `/data/zte-imei-studio` с правами 700: временный каталог `stage-UUID`, журнал `installations/UUID`, Dropbear в `bin`, файлы запуска `start_zte_agent.sh` и `start_zte_imei_studio.sh`. Ключи SSH остаются в `/etc/dropbear`. Штатные каталоги с правами 777 не изменяются.

Очистка выполняется после подтверждённого commit и касается только известных файлов в принадлежащих программе каталогах **завершённых** установок. Каталог без `.install-requested` сохраняется: он может содержать текущую загрузку другого клиента. Неизвестный файл, чужой владелец или устройство, незавершённый журнал и неподтверждённый результат означают сохранение каталога. Резервные копии, история и журналы установки остаются.

При ошибке выполняется попытка отката. Успешный результат подтверждается отдельным чтением исходных файлов, контрольных сумм, прав и состояния процесса. Только после этого приложение архивирует локальное намерение; новая попытка требует ещё одного нажатия пользователем. Текущие временные файлы удаляются лишь после той же полной проверки отката и проверки списка файлов. Если откат не подтверждён, намерение и данные восстановления сохраняются, повторная установка не отправляется. Перезапуск приложения не обходит эту проверку.

Флажок не меняет режим уже отправленной установки и не снимает блокировку чужой или неизвестной операции. Принудительный сценарий подтверждён на подключённом B31; повтор после заводского сброса, установка на B28 и нативный запуск Windows пока не проверены.
