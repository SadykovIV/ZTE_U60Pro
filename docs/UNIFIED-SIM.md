# SIM и eUICC в ZTE U60Pro Manager 1.29

Один комплект **1.29 / агент 2.11.0** предназначен для трёх конфигураций:

| Конфигурация модема | Работа меню eSIM |
| --- | --- |
| Одна карта в физическом слоте | Обычная SIM сохраняет штатные функции. Настоящая eUICC может управляться по маршруту physical 1 / logical 1. |
| Физическая SIM и штатная китайская eSIM | Сохраняется штатный выбор SIM. Загрузка своих профилей на оригинальный чип ZTE не реализована. |
| Вместо внутренней китайской eSIM перепаяна eUICC SIM-карта | Управление заменённой eUICC по physical 2 / logical 2; в физическом слоте может быть другая SIM. |

Наличие слота, IMEI или флаг QMI не подтверждают eUICC. Меню выполняет свежую
проверку маршрута и карты. Управление становится доступным после чтения EID,
полного списка профилей и подтверждённого закрытия сеанса. Ошибка обмена
оставляет тип неизвестным; обычная SIM подтверждается только отдельным
корректным ответом карты и успешным завершением чтения.

## Работа с картой

1. Подключитесь по SSH и откройте существующий раздел **eSIM**.
2. Обновите сведения о картах. Если полная проверка обнаружила одну eUICC,
   приложение выбирает её. При нескольких eUICC явно выберите нужную карту.
   Перед изменением используется свежий снимок именно этой карты и маршрута.
3. Загрузите QR/LPA-строку либо заполните SM-DP+ Address и Activation code.
   Новый профиль устанавливается выключенным. В веб-панели можно переименовать
   профиль с сохранением имени на карте; удалить можно только выключенный профиль.
4. Перед включением профиля выберите соответствующую SIM для сети в штатных
   настройках модема. Для заменённой внутренней карты это **eSIM**. Меню
   управления профилями само не меняет сетевой выбор.
5. После включения проверяются восстановление радио и готовность SIM.
   Регистрацию и мобильный интернет проверяйте отдельно.

Пока выполняется операция eSIM, не переключайте SIM штатным меню и не
извлекайте карту: проверка маршрута и команда модему не являются одной
атомарной операцией. При неподтверждённом закрытии канала обнаружение второй
карты прекращается; автоматического повторения изменения нет.

Выбор карты для профилей и выбор SIM для мобильной сети — разные действия.
Чтение, загрузка, переименование и удаление выключенного профиля не требуют
перехода сети на эту карту. Включение, в том числе перечитывание уже активного
профиля, затрагивает общее радио и требует дополнительных проверок. На известной
B31 используются точные значения двух штатных интерфейсов. На остальных
известных прошивках разрешение зависит от измеренных компонентов и однозначного
состояния QMI с единственной присутствующей целевой картой; неизвестный выбор
при двух картах не разрешает перезапуск радио.

Отказ не запускает обращение к соседнему слоту. Переназначение слотов и
автоматическое переключение сетевой SIM отсутствуют. Два независимых активных
мобильных подключения не заявляются.

## Программа, веб-панель и экран

Настольная программа временно запускает комплектный агент по SSH; постоянная
установка для её операций eUICC не требуется. Загрузка профиля использует
интернет компьютера. Веб-панель использует интернет модема и соответствующий
постоянный агент. Протокол 2 проверяет совместимость и явную цель операции.

Для страницы на экране модема:

1. В разделе **Агент** установите/обновите комплектный агент **2.11.0** и панель.
2. В разделе **eSIM** нажмите **Установить / обновить страницу eSIM**.
   Это обновляет Launcher, но само не обновляет агент.

Launcher использует `--esim-launcher-v2`; старые пары агент/Launcher не получают
доступа к карточным операциям через новый протокол. Состав и порядок экранных
страниц сохраняются обычным установщиком. На известной B31 исправлено имя
оператора; это изменение отображения, не SIM, APN или регистрации.

## Проверенные границы

[Аппаратный отчёт локальной 1.28](INTERNAL-EUICC-LIVE-20261101.md) подтверждает
чтение заменённой eUICC, физическую SIM с HTTPS, экран и запуск после reboot
на одном B31. Интернет через внутреннюю Tele2 там не подтверждён после
неудачных запросов. Загрузка, удаление, переименование и смена профиля в том
прогоне не выполнялись. Исторический результат не подтверждает новый бинарник.
Текущие завершённые проверки — в `VERIFICATION.json` комплекта 1.29.
