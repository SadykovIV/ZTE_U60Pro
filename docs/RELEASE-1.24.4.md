# 1.24.4 — управление по SSH и общая диагностика

Все обычные операции с модемом используют **SSH**. ADB остаётся этапом
первоначальной подготовки SSH. Кнопки штатного Web и агента открывают страницы
в браузере. Потеря SSH не запускает автоматический переход на другой канал.

## Интерфейс

В подготовке четыре вкладки: **«Подключение»**, **«Диагностика»**, **«Агент»**
и русификация экрана. Во вкладке подключения появился компактный блок
**«Доступные способы подключения»**: проверка каналов, браузерные ссылки и
состояние USB ADB. Пароли первоначальной подготовки отделены от обычного SSH-входа.

**«Диагностика»** теперь одна страница исследования устройства и экспорта,
без групп «Подключение и ADB», «Устройство и прошивка», «Сбор и экспорт».
Информация и память остаются в «О модеме». Журнал и его общая кнопка остаются
в «Администрировании», диагностические утилиты — в «Приложениях».
Проверки eSIM и VPN сохраняют свои страницы и ограничения.
Переход по вкладкам не запускает включение ADB, исследование или APDU.

## USB ADB

Переключатель **«Включить ADB»** показывает проверенное состояние отдельно от
неизвестного. Изменение доступно по SSH только на закреплённой B31/configfs-конфигурации.
Перед записью проверяются устройство, boot ID, штатные компоненты, процесс adbd,
USB-функции и незавершённые операции. Меняется только ссылка функции ADB;
настройки автозапуска и другие USB-функции не меняются.

USB-сеть может кратковременно прерваться. Программа повторно проверяет то же
устройство по SSH и подтверждает результат. Без подтверждения в течение
60 секунд модем выполняет одну попытку возврата исходной конфигурации.
Неопределённый исход сохраняет журнал и блокирует повторную запись.
Состояние действует до перезагрузки. На неподдерживаемой конфигурации управление
не разрешается; это не универсальный переключатель для всех прошивок.

Если SSH ещё нет, прежнее включение ADB через поддерживаемый штатный Web
остаётся частью начальной подготовки. Внутренняя ADB-проверка перед установкой
сохраняет привязку к выбранному устройству.

## Исследование и подготовка неизвестной прошивки

Обычное исследование выполняется по SSH без запрета по имени прошивки.
Результат чтения не разрешает запись: каждый установщик заново проверяет
идентичность и свои требования.

Спецификация **revision 8** сохраняет 46 проб и 45 наблюдений. Проверки путей
различают отсутствующего предка и недоступный либо символьный предок. Общая
подготовка Linux ARM64 получает закреплённый статический `zte-timeout`:
системная команда `timeout` не требуется, но ограничения времени сохранены.
Перед запуском проверяются SHA-256, ELF ABI, владелец и тип файла.

Повторная оценка прежнего диагностического ZIP текущим C# evaluator оставляет
два неизвестных условия вместо ложного разрешения установки. Только отдельные
синтетические проверки новых shell-проб дали `prerequisites_met`.
Это доказательство исправления логики, а не успешная установка на другом модеме.
Сам ZIP исследования не устанавливает причину неудачной подготовки без журнала
соответствующей операции.

## Отчёты и языки

Общий диагностический ZIP на обеих платформах включает сохранённое исследование
прошивки, его пробы, действия программы и очищенные трассировки без нового
обращения к модему. В отчёте сохраняются время сбора и версия программы,
создавшей исследование: старое исследование не считается свежей проверкой
подключённого устройства. Повреждённый или небезопасный отчёт пропускается
с объяснением в манифесте; журнал действий остаётся доступен.
Свежее исследование запускается отдельно по SSH.
Постоянный журнал Windows начинается с 1.24.4; действия уже закрытых сеансов
старых версий восстановить нельзя. macOS сохраняет отдельные кнопки офлайн-экспорта
и свежего сбора по SSH. Пропуски перечисляются в `manifest.json`.

Сохранены настройка языка, старые переводы и английские шаблоны сообщений.
Неизвестные состояния и ошибки переключения ADB переведены явно.

## Проверки и границы

Текущий кандидат: macOS **1.24.4 build 42**, Windows **1.24.4.1**;
агент **2.9.0-esim.3** остаётся прежним. Оба архива собраны и независимо
проверены по хэшам исходников, ресурсов и содержимого ZIP. Для macOS проверена
подпись; запуск окончательного пакета через интерфейс пока не проверен, так как
Mac заблокирован. Для Windows сверены PE FileVersion и
AssemblyVersion 1.24.4.1, а встроенный словарь сравнен с исходным семантически.
Пять каталогов macOS содержат 1132 проверенные записи (1117 разных ключей),
Windows — 780 ключей.

Аппаратный цикл ADB остаётся незавершённым. Первая попытка остановилась до
изменения USB из-за отсутствия `setsid`; запуск исправлен на `nohup /bin/sh`.
Следующая проверка встретила сохранённую блокировку eUICC. Процесс уже
завершился, но блокировка может означать незавершённое закрытие канала карты,
поэтому она не удалена. Для продолжения проверки нужна перезагрузка модема.
Успешное аппаратное выключение/включение ADB этой сборкой пока не заявляется.

Локальные проверки текущих изменений:

- macOS: 95 сценариев подготовки, 10 проверок диагностического маршрута,
  21 проверка обзора, 12 проверок информационного/ADB-маршрута,
  11 групп проверок диагностического архива, включая небезопасные сохранённые
  отчёты; исследование прошивки — PASS. Маршрут AppModel — 34 группы PASS.
- Спецификация: 39 Python-проверок проб и полей версии. Установщик: 37 проверок
  и отдельный сценарий отсутствующих каталогов/shared `/tmp`; реальный `/bin/sh`
  выполнялся над синтетической файловой системой без устройства.
- ADB: 15 проверок shell, 22 проверки состояния и 15 сценариев транзакции
  macOS; Windows — 81 проверка backend. UI Windows — 134 проверки и RU/EN
  smoke восьми страниц / 18 секций на macOS. Исследование Windows — 51 проверка,
  общий диагностический экспорт — 47 проверок.
- Каталоги: все прежние ключи и значения сохранены; 88 новых macOS-переводов
  прошли через настоящий L10n в RU/EN, включая составную ошибку ADB, и
  прежние 13 проверок локализации прошли. В Windows добавлен 41 перевод.

Ранее отдельно проверены и сохранены архивы build 41 / Windows 1.24.4.0,
их подпись macOS, ресурсы и каталоги. Эти результаты не подменяют проверку
нового кандидата. [Прежние снимки диагностики](images/README.md#диагностика-1244)
с тремя группами оставлены как история. [Новые снимки](images/README.md#подключение-и-единая-диагностика-1244-build-42)
показывают текущий блок подключения и единую страницу диагностики.
Запуск на Windows и подготовка на прошивке из стороннего ZIP этим циклом
не подтверждены. Перед передачей ZIP просмотрите содержимое: автоматическая
очистка не гарантирует распознавание любых неизвестных личных данных.
