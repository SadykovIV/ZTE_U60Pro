# Проверка известной B04 для выпуска 1.27.1

Приложение **1.27.1**: macOS build **68**, Windows FileVersion **1.27.1.0**;
агент **2.9.0-esim.15**, VPN-контроллер **1.5.0**.

Проверены предоставленные отчёты Windows **1.27.0.0** для
**XCBZ HK MU5250 B04**. В них есть успешный сбор через SSH с root, ARM64 и
стабильной идентичностью устройства. Образ `modem.b16` присутствует: его хэш,
MDM, diag-router, IPA и исходный/локализованный UI совпадают с известными
адаптерами B04. Вариант с отсутствующим образом к этому сбору не относится.
Идентификаторы, частные настройки и исходные журналы здесь не публикуются.

Версия приложения и версия установленных компонентов различаются:
VPN-скрипты `manager.sh`, `firewall.sh` и `service.sh` в отчёте совпали с
выпуском **1.25**, а не с текущим комплектом. Обновление только агента и
веб-панели не обновляет эти VPN-компоненты.

Автоматическая оценка `prerequisites_met` означает наличие проверенных
предпосылок, а не успешное выполнение функции. В отчёте физическая и встроенная
eSIM остаются `unknown`. Нативный запуск Windows EXE в Windows не проверен.

Для определения причины исторического IPA-сбоя не хватает состояния в момент
ошибки: совпадения runtime-маркера с текущими boot/PID, подтверждения процесса
ipacm и целостности IPA-снимка, а также результата конкретного шага подготовки.
В обычный диагностический отчёт 1.27.1 добавлены только текущие метаданные IPA:
совпадение runtime-маркера, число процессов, полнота проверки, целостность снимка
и два флага. Значение `unknown` означает, что проверку подтвердить не удалось;
оно не подменяется отсутствием. Эта проба не меняет устройство и не выводит
boot/PID, хэши либо содержимое конфигурации.
Само сообщение `VPN_IPA_PREPARE_FAILED` не различает эти причины. Зафиксированные
позднее флаги допускаются текущим guard и не доказывают повреждение резервной копии.

## Что сделать после обновления приложения

1. Установить приложение **1.27.1** и подключиться к тому же модему обычной
   кнопкой подключения. Программа сверит сохранённую операцию ADB с устройством;
   при необходимости обновить состояние ADB существующим действием.
2. Если состояние после сверки остаётся неизвестным, штатно перезагрузить модем
   и подключиться снова. Не удалять вручную журналы или блокировки и не
   повторять переключение вслепую. Несовпадение устройства или прошивки требует
   отдельной проверки, а не снятия защиты.
3. В обычном разделе VPN выполнить установку/обновление компонентов VPN.
   Существующая установка использует обновление контроллера и runtime,
   сохраняя профили и настройки Wi-Fi.
4. Выключить VPN Wi-Fi, дождаться подтверждения отключения, затем снова включить.
   Долгоживущий процесс старого guard уже загрузил свои функции; замена файлов
   сама по себе не заменяет этот процесс. Цикл OFF → ON запускает текущие
   сервис и manager. Для IKEv2 это новая явная попытка подключения и возможный
   запрос подтверждения на телефоне.
5. Обновить состояние VPN и прочитать карту/профили eSIM. Успех этих проверок
   оценивается отдельно; предпосылки из старого отчёта его не заменяют.

Новые меню, галочки принудительной установки и заводской сброс для этой
последовательности не требуются. Обновление не является обещанием устранения
невыясненной причины каждого исторического IPA-сбоя.
