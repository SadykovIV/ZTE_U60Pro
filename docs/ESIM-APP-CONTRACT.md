# Контракт eSIM — 1.28 Internal eUICC

- Агент 2.10.0-internal.1 запускает постоянный HTTP API без специальных аргументов; `--esim-check` проверяет компонент, `--esim-rpc` обслуживает закрытую RPC-сессию настольных клиентов.
- Runtime включает закреплённые ARM64 bridge и lpac, production-корни GSMA, SHA-256 и corresponding source. Исходники и версии описаны в `third_party/ESIM-SOURCES.md`; точные хэши — в `Resources/Esim/PROVENANCE.json`.
- Для этого варианта нужна настоящая eUICC, установленная вместо штатной впаянной eSIM. Цель зафиксирована: QMI physical slot 2 / logical slot 2. Оригинальная eSIM ZTE не разблокируется. Историческая проверка съёмной 9eSIM на B31 относится к слоту 1 и не подтверждает работу новой конфигурации.
- Чтение, загрузка, переименование и удаление выключенного профиля адресуют слот 2 независимо от выбранной SIM для сети. Включение профиля требует свежего совпадения обоих штатных признаков выбора SIM со значением 2 перед ES10c и повторно перед изменением общего состояния радио; другой корректный выбор возвращает `esim_slot_not_selected`, а ошибка чтения или некорректное значение — `radio_read_failed`.
- Агент не выполняет SIM remap, не меняет штатный выбор SIM и не переходит к слоту 1 при отказе. Физический слот сохраняет обычное назначение; одновременная работа двух мобильных подключений не заявляется.
- Клиент проверяет идентичность варианта. Веб-панель требует capability target `internal-euicc-slot2`; старый агент с маршрутом slot 1 не считается совместимым. Настольные приложения поставляются с соответствующим закреплённым агентом.
- Перечень операций: чтение карты и профилей, загрузка выключенного профиля, включение выбранного, удаление выключенного и переименование; изменения сериализуются и проверяются повторным чтением.
- Неизвестный результат операции не разрешает автоматическое повторение. Сохранённое состояние явно отличается от свежего. Успех переключения требует проверки карты и возврата радио.
- Desktop HTTPS использует компьютер, web HTTPS — модем. Секреты активации и APDU не входят в диагностический журнал.
- Итог операции содержит дополнительный объект `card`: `kind`, `management`, `reason`, `cleanup_confirmed`. Подтверждённое чтение EID и полного списка после cleanup возвращает `euicc_confirmed / available / eid_and_profiles_read / true`. Обычная SIM возвращает `ordinary_sim / unavailable / isdr_not_found / true`, без snapshot, с `changed=false` и `notifications_pending=false`. Такой результат разрешён только для чтения. Ошибка обмена возвращает `unknown` и не доказывает обычную SIM.

Настольные операции запускают временно размещённый закреплённый агент по SSH; постоянная установка не требуется. Постоянный агент заменяет прежний `/data/zte-agent` для веб-панели и экрана. Launcher обновляется отдельно через альтернативное приложение и использует `--esim-launcher-internal`; смешанные старые/новые пары отклоняются.

Рецепт пересборки: `tools/esim-app/build_runtime.py`, затем `tools/build.py --modem-only`. Полная сборка и тесты описаны в `docs/BUILD.md`.

Определение карты: QMI подтверждает готовую карту и целевой маршрут physical 2 / logical 2; собственный логический канал открывается без AID. SELECT ISD-R с `6A82` при успешном закрытии означает обычную SIM в целевой позиции. Другие статусы и ошибки дают неизвестный тип. Для eUICC читаются EID и полный список профилей. Слот не переназначается; выбор физической SIM для сети не меняет адрес карты для этих операций.

Чтение извлекает только bridge. lpac и корни HTTPS нужны операциям установки и уведомлений. Блокировка bridge — отдельный процессный flock: завершение процесса освобождает его автоматически, файл не удаляется и общая блокировка модема не создаётся.

Совместимость операций радио определяется отдельно от доступа к профилям. Для B04 при подтверждённом отсутствии `modem.b16` требуются точные хэши MDM/diag-router и обе свежие штатные строки версии; недоступный файл, симлинк или ошибка чтения не считаются отсутствием. Перед переключением профиля сохраняются проверки QMI operating mode, целевого маршрута карты и штатного выбора eSIM. Эти адаптеры унаследованы от стандартной ветки, а новая внутренняя конфигурация аппаратно не проверена. Этот fallback покрыт локальными сценариями и не является заявлением об аппаратной проверке B04. Полная матрица и оставшиеся ограничения — в [FIRMWARE-COMPATIBILITY](FIRMWARE-COMPATIBILITY.md).

SELECT ISD-R допускает ответ `61xx`: ограниченный цикл GET RESPONSE дочитывает
его в том же принадлежащем помощнику канале. Только `6A82` первоначального
SELECT, готовая SIM и успешное закрытие подтверждают обычную SIM. Ошибка
последующего GET RESPONSE не доказывает отсутствие eUICC. Ошибка чтения
сохраняет `snapshot_failed` и точный фиксированный `component_error`;
неподтверждённое закрытие отдельно остаётся `card_cleanup_unknown`.

Счётчик протокола `apdu_count` относится только к APDU, переданным через
LPAC relay. Журнал показывает его как `lpac_apdu_count`; внутренние команды
помощника чтения карты в этот счётчик не входят.

Переименование: `operation=rename`, `iccid`, `nickname` и `expected_snapshot`.
Имя содержит от 1 до 64 символов Unicode (не более 256 байт UTF-8), без
краевых пробелов, управляющих символов, переводов строк и bidi-маркеров.
Веб-форма удаляет краевые пробелы до отправки. Имя сохраняется на карте через
ES10c SetNickname; запросы HTTPS, отправка уведомлений и переключение радио
не выполняются. Совпадение имени возвращает `changed=false` без записи.
Перед записью дважды сверяется полный снимок профилей, включая имена; после
закрытия канала перечитывается карта. Успех требует нового имени выбранного
профиля и неизменности остальных данных всех профилей. Неясный результат не
повторяется автоматически. Имя не включается в журнал операций.
