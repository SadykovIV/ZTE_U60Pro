# Публичный контракт eSIM

- Агент 2.9.0-esim.4 запускает постоянный HTTP API без специальных аргументов; `--esim-check` проверяет компонент, `--esim-rpc` обслуживает закрытую RPC-сессию настольных клиентов.
- Runtime включает закреплённые ARM64 bridge и lpac, production-корни GSMA, SHA-256 и corresponding source. Исходники и версии описаны в `third_party/ESIM-SOURCES.md`; точные хэши — в `Resources/Esim/PROVENANCE.json`.
- Для управления профилями нужна физическая eUICC в SIM-слоте. Переключение с восстановлением радио проверено на MU5250 B31; чтение, установка и удаление не требуют B31-хэша. Операции с встроенной eSIM ZTE не включены в этот контракт.
- Перечень операций: чтение карты и профилей, загрузка выключенного профиля, включение выбранного, удаление выключенного; изменения сериализуются и проверяются повторным чтением.
- Неизвестный результат операции не разрешает автоматическое повторение. Сохранённое состояние явно отличается от свежего. Успех переключения требует проверки карты и возврата радио.
- Desktop HTTPS использует компьютер, web HTTPS — модем. Секреты активации и APDU не входят в диагностический журнал.
- Итог операции содержит дополнительный объект `card`: `kind`, `management`, `reason`, `cleanup_confirmed`. Подтверждённое чтение EID и полного списка после cleanup возвращает `euicc_confirmed / available / eid_and_profiles_read / true`. Обычная SIM возвращает `ordinary_sim / unavailable / isdr_not_found / true`, без snapshot, с `changed=false` и `notifications_pending=false`. Такой результат разрешён только для чтения. Ошибка обмена возвращает `unknown` и не доказывает обычную SIM.

Рецепт пересборки: `tools/esim-app/build_runtime.py`, затем `tools/build.py --modem-only`. Полная сборка и тесты описаны в `docs/BUILD.md`.

Определение обычной SIM: QMI подтверждает готовую карту и выбранный физический слот; собственный логический канал открывается без AID; SELECT ISD-R возвращает `6A82`; канал успешно закрывается. Другие статусы и ошибки дают неизвестный тип. Для eUICC читаются EID и профили. Слот не переназначается.

Чтение извлекает только bridge. lpac и корни HTTPS нужны операциям установки и уведомлений. Блокировка bridge — отдельный процессный flock: завершение процесса освобождает его автоматически, файл не удаляется и общая блокировка модема не создаётся.
