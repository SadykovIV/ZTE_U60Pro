# Контракт eSIM — 1.29, агент 2.11.0

Агент запускает постоянный HTTP API без специальных аргументов; `--esim-check`
проверяет компонент, `--esim-rpc` обслуживает закрытую RPC-сессию настольных
клиентов, `--esim-launcher-v2` — совместимую экранную страницу. Runtime включает
закреплённые ARM64 bridge/lpac, production-корни GSMA, SHA-256 и corresponding
source. Источники и версии: `third_party/ESIM-SOURCES.md`,
`Resources/Esim/PROVENANCE.json`.

## Цель и обнаружение

Протокол **2** поддерживает два именованных маршрута:
`removable-euicc-slot1` = physical1/logical1,
`internal-euicc-slot2` = physical2/logical2. Цель обязательна в запросах операций
и сохраняется в снимке карты. Обнаружение перечисляет доступные маршруты;
выбор подтверждённой карты клиентом не переключает SIM для мобильной сети.
Агент не меняет маршрут и не пробует соседний слот при ошибке.

Bridge в обоих режимах требует первую JSON-строку до lock/QRTR: `snapshot` —
ровно `protocol:2,target`; `bridge` — те же поля и `expected_eid` из 32 цифр.
Снимок eUICC и результат обычной SIM возвращают ту же `target`. После snapshot
bridge передаёт фиксированный `cleanup_confirmed` только при подтверждённом
закрытии. Обнаружение не продолжает другую карту после сбоя без этой квитанции. Каждый новый
сеанс проверяет фактический маршрут, а повторное открытие канала — EID.

QMI подтверждает выбранную пару physical/logical; собственный логический канал
открывается без AID. Только первоначальный SELECT ISD-R с `6A82`, готовая SIM
и успешное закрытие подтверждают обычную SIM. `61xx` обрабатывается ограниченным
GET RESPONSE на том же канале. Ошибки, неизвестные ответы и неподтверждённое
закрытие не превращаются в отсутствие eUICC.

Результат `card` содержит `kind`, `management`, `reason`, `cleanup_confirmed`.
Чтение EID и полного списка после cleanup даёт
`euicc_confirmed / available / eid_and_profiles_read / true`.
Обычная SIM — `ordinary_sim / unavailable / isdr_not_found / true`, без snapshot,
с `changed=false` и `notifications_pending=false`; такой исход разрешён только
для чтения. Штатная китайская eSIM не получает поддержку своих QR от одного
наличия слота или vendor API.

## Изменения и радио

Чтение, загрузка, переименование и удаление выключенного профиля адресуют
подтверждённую карту независимо от сетевого выбора SIM. Изменение требует
явной цели и свежего согласованного снимка; проверяются EID, полный список
профилей и cleanup; переименование дополнительно сверяет имена. Новый профиль загружается выключенным; активный
удалять нельзя. При неизвестном результате требуется новое чтение.

Включение и перечитывание активного профиля дополнительно проверяют сетевую
SIM до ES10c и перед изменением общего радио. На измеренной B31 точные пары
`get_sim_info.current_sim_slot` / `zte_get_current_slot_info.current_sim_slot`:
физическая SIM `(1,0)`, внутренняя `(2,2)`. Это не общее разрешение трактовать
любые `0/1` как один слот. Другие поддержанные прошивки требуют точного радио-
профиля, полной QMI-топологии с единственной присутствующей целевой картой и
отсутствия других назначенных подписок; неоднозначная конфигурация двух карт не разрешает
радиопереход. Для первой активации на пустой единственной карте допускается отсутствие
назначенного USIM; после радиоперехода готовность USIM обязательна.
Нечитаемое состояние не становится подтверждённым выбором.

Профили радио: B31, FLY B27/B28, XCBZ HK B04. Для B04 с отсутствующим
`modem.b16` нужны доказанное отсутствие, точные MDM/router и обе строки версии;
ошибка чтения и симлинк не считаются отсутствием. Наличие адаптера не доказывает
аппаратную проверку операции. SIM remap и автоматический сетевой выбор отсутствуют.

## Транспорт и данные

Desktop использует HTTPS компьютера через ограниченный relay; веб-панель —
интернет модема. Проверяются допустимые адреса, TLS, имя сервера и production-
корни. Системное хранилище доверия не изменяется. Полные идентификаторы/APDU
остаются в закрытом протоколе; коды активации, ключи и пароли не пишутся в логи.

Переименование хранится на карте, до 64 Unicode-символов, без переключения
профиля или доступа в интернет. Общий фоновый опрос состояния модема не
выполняет карточные APDU; обнаружение и чтение запускаются в разделе eSIM.
