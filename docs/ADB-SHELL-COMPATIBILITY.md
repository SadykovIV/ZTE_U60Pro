# Исправление ответов ADB в 1.23.4

## Причина

В двух диагностических архивах Windows 1.23.3 от 3 октября ADB обнаруживает USB-модем. Команды идентификации возвращают `uid=0` и `aarch64`. Вывод заканчивает строки последовательностью `CR CR LF`. Прежние обработчики допускают только `LF` или `CR LF`, поэтому теряют удалённый код завершения и факты исследования. Дальнейшие пробы пропускаются.

В архиве случайный маркер команды обезличен после обработки ответа. Архивы подтверждают форму ответа и ошибку приложения; проверить исходный nonce по ним невозможно.

## Изменение

Windows и macOS принимают три формата окончания строк в служебном завершении ADB: `LF`, `CR LF`, `CR CR LF`. Для текстовых ответов нормализуются эти окончания строк: идентификация, факты исследования и ответы установщика. Бинарный вывод сохраняется.

Проверки уникальности маркера, удалённого кода, локального завершения ADB и привязки к устройству остаются обязательными. Неизвестная прошивка должна исследоваться через доступный ADB; автоматическая установка разрешается только при прохождении существующих проверок.

## Повторная проверка на Windows

1. Распакуйте portable-сборку 1.23.4 в отдельный каталог. Сохраняйте каталог `Resources` рядом с EXE.
2. Подключите только нужный модем через USB. Если ADB уже отвечает, повторно включать его не требуется.
3. Запустите «Исследование прошивки» в режиме ADB и сохраните новый ZIP. Ожидается выполнение остальных проб после `fingerprint` и `identity`, а не сообщение о пропавшем удалённом коде.
4. Проверьте результат подготовки SSH в разделе подключений. Если она остановится, сохраните журнал с причиной. Для определения следующих ограничений нужны новый ZIP и журнал подготовки.

Сборка проверяется на воспроизведённых ответах и программных сценариях. Запуск на модеме друга и непосредственно в Windows требует повторной проверки у владельца. Работоспособность всех функций его прошивки по прежним неполным архивам определить нельзя.
