# Подготовка и публикация выпуска

Текущий единый выпуск — **1.29**: macOS build **71**, Windows FileVersion
**1.29.0.0**, агент **2.11.0**. Предыдущий опубликованный tag — **v1.27.2**;
локальная 1.28 является отдельным историческим комплектом.

1. Согласуйте версии клиентов, агента, заметки выпуска и комплектные хэши.
   Выполните подходящие локальные проверки и полную сборку по `docs/BUILD.md`.
2. Подготовьте обе desktop-сборки и соответствующие исходники компонентов.
   Упакуйте в новый пустой каталог:

   ```sh
   python3 tools/package_release.py --output-dir release/1.29 --previous-release v1.27.2 --build-source-commit "$(git rev-parse HEAD)"
   ```

   Для публичного выпуска не добавляйте `--local-only`: архив зависимостей
   получает URL под `v1.29`. Скрипт ничего не публикует. Он проверяет связь
   исходников, ресурсов и готовых ZIP; `build-source-commit` справочный.
3. Сохраните точные завершённые проверки в `VERIFICATION.json`. Исторический
   аппаратный прогон, локальный тест и новая проверка на устройстве — разные
   результаты. Не превращайте старый B31 pass в проверку нового бинарника,
   B27/B28/B04 или нативного Windows.
4. Проверьте состав новых Git-файлов и `git diff --cached`, затем исходники и
   все архивы:

   ```sh
   python3 tools/audit_public.py --artifacts --artifact-dir release/1.29
   ```

   Аудит исходников использует `git ls-files`: новые файлы должны быть учтены
   в индексе. Приватные evidence, дампы, vendor-бинарники, SIM/VPN-профили,
   ключи и пароли не входят в публичный проект. Дополнительные частные строки
   можно проверять через `--forbidden-file` с JSON вне репозитория.
5. Зафиксируйте проверенные исходники, зависимости и документацию. Публикуйте
   tag конкретного коммита и комплект с краткими заметками RU/EN. При работе
   через `gh release create` используйте `--verify-tag`, `--notes-file` и явный
   список проверенных файлов; draft позволяет сверить assets до публикации.
6. После загрузки сравните удалённые имена, размеры и SHA-256 со сборкой,
   проверьте текст и ссылки на macOS/Windows. Только завершённая публикация
   позволяет обновить указатель Latest. Не перезаписывайте старые комплекты.

Автоматического push, публикации или соединения с модемом в сборочных скриптах нет.
