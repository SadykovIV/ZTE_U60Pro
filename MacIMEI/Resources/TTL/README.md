# Настройка IPv4 TTL для MU5250 CN B31, FLY B28 (B13) и XCBZ HK B04

`manager.sh` управляет собственными цепочками mangle и настройками в `/data/zte-imei-ttl`. Исходящий TTL задаётся `--ttl-set`; входящий повышается `--ttl-inc` на этапе FORWARD по направлению в `br-lan`.

Интерфейсы выбираются по действующим мобильным маршрутам по умолчанию. Значения — `off` либо целое число 1–255. Отключение удаляет только правила приложения. IPv6, системный `ip_default_ttl` и содержимое NV/EFS не изменяются.

Автозапуск: собственный include fw3, обработчик iface и проверяемый блок в существующем `/etc/rc.local`. Отдельный новый Sxx-link недостаточен на этой прошивке: overlay `/etc` подключается уже во время загрузки.

B28 определяется по собранным контрольным суммам modem.b16, diag-router, ipacm и штатного скрипта ускорения. Установка, изменение и отключение проверяются отдельно для B28 и B31. Проверка правил не подтверждает TTL реальных пакетов: поле verification остаётся unverified.

В архивах B04 встречались как недоступный `/firmware/image/modem.b16`, так и образ с SHA-256 `c57e063d390983229dfc53aa87380b3d4655ee8daa1c748e1a032ac90cd0df81`. Оба варианта требуют собранных SHA-256 `zte_topsw_mdm` и `diag-router`, а также проверок ядра и iptables. Неизвестный имеющийся образ не принимается по названию прошивки. Его `ipacm` и `ipacm_switch.sh` побайтно совпадают с B31. При ранней загрузке проверка не зависит от готовности vendor RPC. На B04 подтверждена совместимость собранных компонентов и тесты установки/отключения на стенде; TTL реальных пакетов ещё требует проверки на устройстве.

При явном применении TTL программа обновляет менеджер из 1.24.20 (SHA-256 `a70afc13…`) до текущего. Настройки, цепочки и загрузочные обработчики сохраняются. Предыдущий менеджер, его контрольная сумма, CID и ожидаемая новая сумма остаются в приватном каталоге `/data/zte-imei-ttl-upgrade-a70afc13c3645f64b5fd937162e7d403e133bcfa0a2da0e565d39a693f9ab488`. Если питание пропало между заменой суммы и менеджера, следующее явное применение завершает эту же замену по проверенной копии. Кнопка проверки ничего не обновляет; незавершённая TTL-транзакция или неизвестные файлы блокируют замену.
