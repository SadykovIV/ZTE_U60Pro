# Диагностика — 1.24.14

Раздел **«Подготовка модема → Диагностика»** содержит два действия.
Просмотр журнала действий остаётся в администрировании. Настройки подключения
и ADB остаются во вкладке подключения; iperf3 и tcpdump — в приложениях.

## Логи и журналы

**«Сохранить логи и журналы»** собирает подготовку, подключения, ошибки программы
и операций с модемом. При готовом SSH добавляются свежие системные журналы,
журнал ядра и журналы установленных компонентов. При недоступном SSH сохраняется
локальный ZIP с объяснением причины. Постоянный агент для сбора не нужен.

Журнал содержит sessionID, operationID и requestID, время, длительность,
адрес подключения, коды завершения, очищенные команды и вывод. Stdin команд,
тела авторизации HTTP и cookies не сохраняются. Трассировки лежат в Activity/Traces.

ZIP содержит application.json, README.txt, manifest.json с SHA-256 очищенных
файлов, Activity, наборы журналов Diagnostics, старые текстовые логи и
SetupBackups/.../installation.log. Файлы исследованных прошивок сюда не входят.
Ключи, connection.json, NV/EFS, конфигурационные бэкапы и хранилища VPN-профилей
не копируются. Известные секреты, VPN-ссылки и номера IMEI/SIM скрываются;
сетевые адреса, CID и пути могут оставаться. Произвольные секреты без узнаваемого
формата автоматически распознать нельзя.

Для macOS сохраняются до 64 МиБ очищенных данных и 10000 файлов, до 2 МиБ
на файл, сначала новые. Для JSONL сохраняется конец; неполные строки пропускаются.
Пропуски и сокращения перечисляются в manifest.json. Трассировка сохраняет до
16 КиБ команды и по 64 КиБ вывода; раздел системного журнала — до 512 КиБ.

## Данные для адаптации прошивки

Одно действие выполняет свежую проверку устройства, исследование прошивки
и сбор файлов компонентов, которые программа анализирует или изменяет.
Весь результат находится в ZIP; на экране показываются ход сбора и итог,
без длинного списка проверок. Требуется SSH. Сбор не меняет модем и не
отключает проверки при последующих операциях записи.

[Состав архива и ограничения](../docs/FIRMWARE-ADAPTATION-DATA.md).

## Свой агент

При первой настройке выполните автоматическую подготовку: она установит SSH, агент и его сценарий запуска. После подключения откройте **Подготовка модема → Агент → Выбрать свой файл**.

Допускается исполняемый ELF64 little-endian Linux AArch64, до 64 МиБ. Проверяются заголовок, таблица сегментов, точка входа и путь интерпретатора. Файл повторно читается перед установкой; его SHA256 должен совпасть с показанным при выборе. Наличие динамического загрузчика проверяется на модеме.

Заменяется только /data/zte-agent. Существующие SSH, пароль, сценарий запуска, веб-панель и профили не меняются. Новый файл запускается с правами root и существующими параметрами. Работа процесса подтверждается через /proc; совместимость стороннего API с нашей панелью, экраном и VPN не гарантируется.

Перед заменой установщик сохраняет одну предыдущую версию в /data/zte-agent-installer, проверяет SHA256 и CID, затем создаёт постоянный маркер незавершённой операции. Ошибка запуска вызывает попытку отката. После обрыва питания/связи нажмите **Проверить агент**, затем **Восстановить предыдущий агент**. Повторная установка при незавершённой операции блокируется. Восстановление тоже проверяет CID и хэш копии.

## Проверки

На Mac ARM64: python3 tools/check_diagnostics.py, python3 Tests/agent_installation_test.py, ./build.sh.

Swift-проверки используют подставные транспорты; shell-проверки — временную файловую систему с подставным управлением процессом. Произвольный сторонний агент не устанавливался на пользовательский модем. Сбор диагностики и проверка состояния штатного агента дополнительно проверены на реальном B31; журнал logread на нём может быть недоступен, что отражается в отчёте.
