# Диагностика и установка агента — 1.9.0

Меню: **О модеме → Подготовка модема → IMEI → TTL → VPN → Приложения (beta) → Администрирование**.

- **О модеме:** сведения о системе, память, диски и сбор диагностики. Сведения читаются через SSH; успешная сверка с B31 для диагностики не требуется.
- **Подготовка модема:** подключение, пароль веб-интерфейса, разблокировка ADB, настройка SSH, установка агента и русификация. Вкладка **Агент** позволяет проверить установленный файл, поставить штатную версию, выбрать свой файл и восстановить предыдущую версию.
- **IMEI:** чтение, смена и резервные копии NV550/EFS; описание порядка операции. Свежая проверенная копия перед записью обязательна.
- **TTL:** точный исходящий TTL и прибавка +N к входящему IPv4, описание механизма.
- **VPN:** проверка/установка/обновление компонентов. Импорт и выбор профилей остаются в агенте на модеме; используется отдельная сеть WiFi с VPN.
- **Приложения (beta):** пакеты, каталог и место для установки.
- **Администрирование:** службы доступа, пользователи SSH, бэкапы конфигураций/модемной/пользовательской части и журнал.

## ZIP

Кнопки доступны в «О модеме → Диагностика» и «Администрирование → Журнал действий»:

1. **Экспортировать журналы в ZIP** — без обращения к модему.
2. **Собрать с модема и сохранить ZIP** — сначала прочитать свежий набор. При недоступном соединении сохраняются локальные данные с указанием причины.

Сбор не меняет политику допуска операций записи. Отдельный раздел может завершиться ошибкой на другой прошивке; остальные данные сохраняются. После трёх подряд ошибок соединения оставшиеся запросы пропускаются. Перезагрузка во время сбора отмечается в manifest.json.

Журнал содержит sessionID, operationID и requestID, временные метки, длительность, адрес подключения, коды HTTP/RPC/процесса, проверки хэшей прошивки, очищенные команды и текстовый вывод. SSH и ADB сохраняют частичный вывод при тайм-ауте. Для команд stdin не сохраняется; HTTP сохраняет метаданные, без тел авторизации и cookies. Трассировки лежат в Activity/Traces.

ZIP содержит application.json, README.txt, manifest.json с SHA256 файлов после очистки, Activity, диагностические наборы, очищенные старые .log и installation.log. Ключи, connection.json, NV/EFS и прочие бэкапы, VPN-профили в архив не копируются. Известные секретные поля, VPN URI и длинные номера IMEI/SIM скрываются. Произвольный секрет без узнаваемого формата нельзя гарантированно распознать; сетевые адреса, CID и пути остаются. Перед отправкой можно просмотреть архив локально.

Пределы: 64 МиБ исходных очищенных данных, до 10000 файлов, 2 МиБ на файл; сначала новые файлы. Для длинных JSONL сохраняется конец, неполные строки пропускаются. Все пропуски и сокращения перечислены в manifest.json. Отдельная трассировка сохраняет до 16 КиБ команды и по 64 КиБ вывода; полные диагностические разделы — до 512 КиБ. До версии 1.9.0 подробные трассировки не создавались.

## Свой агент

При первой настройке выполните автоматическую подготовку: она установит SSH, агент и его сценарий запуска. После подключения откройте **Подготовка модема → Агент → Выбрать свой файл**.

Допускается исполняемый ELF64 little-endian Linux AArch64, до 64 МиБ. Проверяются заголовок, таблица сегментов, точка входа и путь интерпретатора. Файл повторно читается перед установкой; его SHA256 должен совпасть с показанным при выборе. Наличие динамического загрузчика проверяется на модеме.

Заменяется только /data/zte-agent. Существующие SSH, пароль, сценарий запуска, веб-панель и профили не меняются. Новый файл запускается с правами root и существующими параметрами. Работа процесса подтверждается через /proc; совместимость стороннего API с нашей панелью, экраном и VPN не гарантируется.

Перед заменой установщик сохраняет одну предыдущую версию в /data/zte-agent-installer, проверяет SHA256 и CID, затем создаёт постоянный маркер незавершённой операции. Ошибка запуска вызывает попытку отката. После обрыва питания/связи нажмите **Проверить агент**, затем **Восстановить предыдущий агент**. Повторная установка при незавершённой операции блокируется. Восстановление тоже проверяет CID и хэш копии.

## Проверки

На Mac ARM64: python3 tools/check_diagnostics.py, python3 Tests/agent_installation_test.py, ./build.sh.

Swift-проверки используют подставные транспорты; shell-проверки — временную файловую систему с подставным управлением процессом. Произвольный сторонний агент не устанавливался на пользовательский модем. Сбор диагностики и проверка состояния штатного агента дополнительно проверены на реальном B31; журнал logread на нём может быть недоступен, что отражается в отчёте.
