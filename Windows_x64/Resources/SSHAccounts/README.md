# Managed SSH accounts and access services

The native app uses its protected key-only SSH connection on port 2222 for these operations. It cannot stop that endpoint, replace root credentials, or disable USB ADB. Service changes affect only the current boot; existing startup configuration is preserved.

`access-services.sh` reports stock WEB (80), dashboard (8080), agent (9090), management SSH (2222), user SSH (2223), and USB ADB. Start/stop/restart is offered only for verified agent, dashboard, and managed-user SSH binaries and startup configurations. Socket ownership is checked through `/proc` before signaling the exact listener PID. Unknown binaries, launchers, foreign listeners, writable binary directories, and unsupported services are read-only. A standard agent launcher is accepted through a strict grammar that validates its shell-quoted password without printing it. It is copied to a private stage before execution. No agent or web per-user accounts are invented: those services use their existing shared credentials.

`delete-ssh-user.sh delete STAGE CID USER LOCK_TOKEN` removes only a user with UID 50000–59999, the application's home/GECOS/group/doas layout, and a matching completed creation journal. Root and system accounts are rejected. The calling app must hold the global device lock; the script also holds the account lock and verifies the firmware and device CID. Active user processes, extra secondary group memberships and foreign listeners cause refusal. The dedicated password listener is briefly stopped when running; existing connected users must finish their sessions first.

Before replacing any account file, the script saves exact passwd/group/shadow/doas copies in a root-private transaction directory. Each file replacement is atomic, while the durable active marker records the multi-file operation. On an ordinary failure, rollback restores only bytes still matching this transaction and preserves concurrent external changes. The home directory is moved to `/data/zte-imei-admin/archive/TRANSACTION/USER`, behind a root-only directory. It is never recursively deleted. The shared group, service binaries, management SSH and boot hooks remain.

After an interrupted deletion, `delete-ssh-user.sh recover STAGE CID LOCK_TOKEN` rolls back the verified deletion journal. It never treats an unfinished create transaction as a deletion. An incomplete or conflicting recovery leaves the active marker for further inspection. Native backups are private; passwords are never supplied to deletion and account password hashes remain confined to protected backups.

Build packaging already includes `Resources/SSHAccounts/*`; `SHA256.json` covers both new scripts. Tests relocate the complete scripts to a synthetic filesystem and replace privileged utilities; they do not access a device or the host account databases.
