# VPN для MU5250 B31

Комплект приложения 1.8.0: собственный менеджер `/data/zte-vpn`, Mihomo 1.19.31, контроллер профилей `vpnctl`, обновление агента 2.7.0-esim.2 с eSIM и панели RU/EN. Установка доступна из «Настройки VPN» после проверки прошивки и системных компонентов; загрузка компонентов из интернета не нужна. SSClash-Go не требуется и его настройки не перезаписываются.

VLESS-профиль импортируется из ссылки, проверяется ядром и сохраняется приватно на модеме. Поддержаны TCP, WebSocket, gRPC и XHTTP, TLS/REALITY, включая проверенный XHTTP + ML-KEM. Неизвестные или противоречивые параметры отклоняются. `spx` сохраняется в исходной ссылке, но это ядро его не использует. Импорт не переключает соединение: нажмите «Активировать». Активный профиль нельзя удалить; до 32 профилей. Общий статус не возвращает ключи и исходные ссылки. Полные параметры доступны по явному запросу «Параметры профиля» в авторизованном агенте; ответ не кэшируется.

Новая VPN-сеть по умолчанию называется ZTE-VPN и использует оба гостевых AP. При первой настройке копируются пароль и параметры защиты основного Wi-Fi 5 ГГц; если они недоступны или непригодны, используется основная сеть 2,4 ГГц. Последующие изменения основного пароля автоматически не синхронизируются. Обновление компонентов сохраняет название и пароль уже настроенной гостевой сети. Приложение и дисплей показывают фактические названия обеих гостевых сетей. Это отдельный мост 192.168.50.1/24. TCP, UDP и клиентский DNS передаются через VPN. IPv6 этой сети заблокирован. При недоступном VPN прямого выхода нет; доступ к основной локальной сети закрыт. Mesh и работающий сторонний прокси несовместимы с этой настройкой. IPA должен быть выключен (текущее управление TTL уже делает это). Основной Wi-Fi не переводится на VPN.

Защита состоит из независимого nftables-фильтра, ebtables для гостевых интерфейсов и правил перенаправления iptables. На B31 новый rc.d-сервис сам по себе не гарантирует запуск при загрузке, поэтому проверяемый блок добавляется в существующий `/etc/init.d/network` до запуска netifd. При ошибке проверки гостевые AP выключаются. Исходные настройки сохранены в `/data/zte-vpn/backup`.

Переключение профиля использует атомарно публикуемый журнал с восстановлением при прерывании. Обновление агента сохраняет пароль/PIN и резервную копию предыдущей установки. Сеть работает без компьютера. Экран модема использует штатный переключатель гостевой сети с новым названием «WiFi с VPN»; он отображает включение сети, а не доступность удалённого VPN-сервера.

Сборка: исходники контроллера в `ModemAgent/vpnctl`, адаптера API в `ModemAgent/agent/src/vpn.rs`, интерфейса в `ModemAgent/web-app/src/features/network/VpnTab.tsx`. После сборки ARM64 musl и web выполните `python3 MacIMEI/tools/package_vpn.py`, затем `MacIMEI/build.sh`. Скрипты runtime встроены в контроллер для проверки целостности; после изменения скриптов нужно пересобрать контроллер, обновить его SHA в адаптере и пересобрать агент.

Mihomo: https://github.com/MetaCubeX/mihomo/tree/v1.19.31 (GPLv3, лицензия рядом). Бинарник взят из уже проверенного комплекта SSClash на этом модеме; SHA указан в SHA256.json. uhttpd: OpenWrt 23.05.4, пакет uhttpd_2023-06-25-34a8a74d-2_aarch64_generic.ipk; исходники https://github.com/openwrt/uhttpd/tree/34a8a74d. Уведомление об авторских правах сохранено рядом. Пользовательские профили в комплект приложения не входят.

Обновление 1.7.0: ссылка профиля отображается открытым текстом по запросу владельца. Импорт принимает `x_padding_bytes` как синоним `extra.xPaddingBytes`, проверяя совпадение при указании обоих. Контроллер 1.0.1 обновляется из известных 1.0.0 с резервной копией и обновлением закреплённых SHA в раннем запуске сети. HTML панели отдаётся с `Cache-Control: no-store, no-cache, must-revalidate`; JS/CSS предыдущей версии сохраняются для уже открытых браузеров. Разделы загружаются вместе с приложением, ошибка отдельного раздела оставляет доступным меню и кнопку перезагрузки.

Версия 1.7.0: программа отвечает только за проверку и установку компонентов. Импорт,
выбор, переименование и просмотр профилей доступны в агенте. Переименование меняет
только отображаемое название; исходная ссылка, конфигурация и процесс VPN сохраняются.

В версии 1.8.0 добавлены постоянные страницы **внутри штатного лаунчера**: главный
экран → настройки → «О модеме» → VPN. На третьей странице — система, свободная RAM,
память приложений и время работы. На четвёртой — WiFi с VPN и выбор профиля с
подтверждением. Используются штатные шрифты, цвета, сенсор и ориентация дисплея.
Перелистывание работает в обе стороны, внизу четыре индикатора. Страницы запускаются
после перезагрузки без компьютера; агент может выбрать страницу, но не обходит
штатную блокировку дисплея. Данные обновляются на модеме.

Компонент устанавливается и восстанавливается кнопкой установки компонентов VPN.
Проверяются точные хэши B31 и оригинального/русифицированного UI. Штатный бинарник
и init-скрипт не изменяются; при ошибке расширения служба возвращается к обычному
лаунчеру. Установщик сохраняет резервную копию и восстанавливает прерванную замену.
Технические детали и сборка: `ModemAgent/launcher/README.md`.


## Название и пароль гостевой VPN-сети

Явная команда `configure_wifi` принимает через stdin JSON поля `ssid`, `password_mode` (`main`, `custom`, `preserve`) и `password` только для `custom`. SSID занимает от 1 до 32 байт UTF-8 и не содержит управляющих символов. Новый собственный пароль содержит 8–63 печатных ASCII-символа или 64 шестнадцатеричных символа; применяется WPA2-PSK/CCMP. Режим `main` копирует текущий основной пароль один раз. Режим `preserve` сохраняет текущие ключи двух AP и доступен только для уже настроенной VPN-сети.

До первой активации настройки сохраняются в `/data/zte-vpn/wifi-settings.json` с правами `0600`; первая активация применяет их. Для уже настроенной сети сохранение разрешено только при выключенных обоих гостевых AP, привязанных к `vpn`/`br-vpn`. Меняются только настройки этих AP и выполняется `uci commit wireless`; Wi-Fi не перезапускается и сеть не включается. Следующее явное включение применяет сохранённые параметры. Прерванное или неуспешное сохранение оставляет маркер, блокирующий включение до повторного успешного явного сохранения.

Пароли не возвращаются в status и не попадают в аудит. При работе из приложения контроллер проверяет переданный `lock_token` и приватные права общего lock-каталога, затем использует уже удерживаемую приложением блокировку. Обновление контроллера проверяет и резервирует совместимый `configure.lua` вместе с остальными компонентами; само обновление не меняет название сети и пароль.
